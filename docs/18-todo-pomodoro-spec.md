# 18. 투두리스트·뽀모도로 연동 기능 명세

작성일: 2026-08-23  
대상: Windows 11 전용 Desktop Pet MVP  
상태: 핵심 MVP 구현 완료, Windows 수동 검증 및 고급 축하 연출 보강 전

## 0. 구현 현황

2026-08-23 기준으로 다음 핵심 흐름을 구현했다.

- `todo.json` 원자 저장과 손상 파일 보존
- 할 일 추가·수정·완료 전환·삭제와 집중 항목 단일 선택
- 미완료 우선 정렬과 완료 직후 500ms 지연 이동
- Focus 시작 시 선택 항목 ID·이름 고정
- 정상 Focus 종료 후 `완료하기`·`계속하기`·`다음 집중` 선택
- Skip·Stop 시 연결 해제 및 할 일 상태 유지
- 마지막 미완료 항목을 직접 완료할 때만 `todo://all-completed` 1회 발생
- 새 항목 추가·완료 해제 후 축하 재발동
- 펫 우클릭 메뉴에서 여는 독립 `todo` 창과 작은 타이머 분리
- 설정·우클릭 메뉴와 통일한 WinDbg형 메뉴·리본·명령줄·상태바 UI
- 기본 점프·광원 축하와 타이머 화면 축하 문구

아직 남은 범위는 Windows 실제 입력·재시작 복원 수동 검증, 중앙 안전 이동·말풍선·색종이·효과음, 움직임 줄이기 및 긴급 중지 중 축하 즉시 취소다.

## 1. 목표

독립 `todo` 창에 간단한 투두리스트를 제공한다. 사용자는 감자펫 우클릭 메뉴에서 창을 열어 할 일을 직접 추가하고 완료할 수 있으며, 원하는 항목 하나를 선택해 뽀모도로 집중 세션과 연결할 수 있다. 마지막 미완료 항목을 완료하면 감자봇이 전체 완료를 축하한다.

핵심 사용자 흐름:

```text
할 일 추가
  → 집중할 항목 선택
  → 뽀모도로 시작
  → 집중 세션 정상 종료
  → 완료하기 또는 계속하기 선택
  → 전체 완료 시 감자봇 축하
```

## 2. MVP 범위

### 2.1 포함

- 단일 현재 투두리스트
- 할 일 추가, 내용 수정, 완료·미완료 전환과 삭제
- 미완료 항목 우선 표시
- 집중할 할 일 한 개 선택
- 선택한 할 일과 뽀모도로 집중 세션 연결
- 정상 집중 종료 후 `완료하기` 또는 `계속하기` 직접 선택
- 투두리스트 전체 완료 축하 이벤트
- 할 일과 축하 설정의 로컬 저장
- 키보드만으로 기본 조작 가능

### 2.2 제외

- 계정, 로그인과 클라우드 동기화
- 여러 목록, 프로젝트, 태그와 협업
- 마감일, 반복 일정과 캘린더 연동
- 할 일별 예상 뽀모도로 횟수
- 타이머 종료에 따른 자동 완료
- 포인트, 레벨과 꾸미기 자동 해금

## 3. 화면 구성

`timer` 창은 펫 위의 작은 시간 말풍선으로 유지하고, 투두 편집과 세션 종료 선택은 일반 앱 크기의 독립 `todo` 창에서 처리한다. `todo` 창은 펫 우클릭 메뉴의 `투두리스트` 항목으로 열며 닫아도 데이터와 타이머는 유지된다.

### 3.1 타이머 영역

- 현재 단계: 집중, 짧은 휴식, 긴 휴식, 일시정지
- 남은 시간
- 현재 집중 항목 이름. 선택하지 않았다면 `선택된 할 일 없음`
- 시작, 일시정지, 재개, 건너뛰기와 중지 버튼

### 3.2 투두리스트 영역

- 빠른 입력창과 `추가` 버튼
- 각 항목의 완료 체크박스
- 집중 항목 선택 버튼
- 내용 수정과 삭제 메뉴
- 완료 개수와 전체 개수. 예: `2/5 완료`
- 완료 항목 접기·펼치기

기본 정렬은 미완료 항목을 위에 두고 각 그룹 안에서는 생성 순서를 유지한다. 완료 처리 직후 항목을 즉시 재정렬하지 않고 약 500ms 뒤 이동시켜 사용자가 결과를 확인할 수 있게 한다.

### 3.3 빈 상태

- 문구: `오늘 할 일을 하나 적어보자!`
- 빈 목록에서는 전체 완료 축하 이벤트를 실행하지 않는다.

## 4. 할 일 동작 규칙

### 4.1 추가

- 앞뒤 공백을 제거한 뒤 저장한다.
- 빈 문자열은 추가하지 않는다.
- 한 항목은 최대 200자다.
- 같은 문구의 항목도 서로 다른 항목으로 추가할 수 있다.
- 새 할 일은 미완료 상태로 생성된다.
- 전체 완료 상태에서 새 할 일을 추가하면 축하 이벤트를 다시 발동 가능한 상태로 전환한다.

### 4.2 수정

- 수정 결과가 빈 문자열이면 저장하지 않고 이전 내용으로 복원한다.
- 완료 항목의 내용도 수정할 수 있다.
- 내용 수정만으로 완료 상태나 축하 발동 상태는 바뀌지 않는다.

### 4.3 완료와 미완료

- 체크박스를 선택하면 완료 시각을 기록한다.
- 체크를 해제하면 완료 시각을 제거한다.
- 완료 항목을 미완료로 되돌리면 전체 완료 축하를 다시 발동할 수 있다.
- 마지막 미완료 항목을 완료한 경우 `TODO_ALL_COMPLETED` 판정을 수행한다.

### 4.4 삭제

- 미완료 항목 삭제로 목록의 모든 남은 항목이 완료 상태가 되더라도 축하 이벤트를 실행하지 않는다.
- 선택된 집중 항목을 삭제하면 선택을 해제한다.
- 실행 중인 집중 세션에 연결된 항목을 삭제하려 하면 확인창을 표시한다.
- 삭제를 확정해도 타이머는 계속 실행되며 해당 세션은 `연결된 할 일 없음` 상태가 된다.

## 5. 뽀모도로 연동

### 5.1 집중 항목 선택

- 미완료 항목 한 개만 현재 집중 항목으로 선택할 수 있다.
- 다른 항목을 선택하면 기존 선택은 자동 해제된다.
- 선택 없이도 일반 뽀모도로를 시작할 수 있다.
- 집중 세션 실행 중에는 연결 항목을 자동으로 바꾸지 않는다.

### 5.2 세션 시작

- 시작 시점의 선택 항목 ID와 이름을 세션에 연결한다.
- 이후 항목 이름을 수정해도 연결은 ID 기준으로 유지한다.
- 세션 중 UI에는 연결 항목을 강조 표시한다.

### 5.3 집중 세션 종료

연결된 미완료 항목이 있으면 다음 선택지를 표시한다.

- `완료하기`: 항목을 완료 처리하고 전체 완료 여부를 판정한다.
- `계속하기`: 항목을 미완료로 유지한다.
- `다음 집중 시작`: 항목을 유지한 채 다음 집중 세션을 시작한다. 자동 시작 설정이 꺼져 있으면 시작 준비 상태까지만 전환한다.

타이머 종료만으로 할 일을 자동 완료하지 않는다. 연결 항목이 없거나 이미 삭제·완료된 경우 기존 뽀모도로 종료 흐름만 실행한다.

### 5.4 중지와 건너뛰기

- 사용자가 세션을 중지해도 항목 상태는 변경하지 않는다.
- 집중 단계를 건너뛰어도 완료 선택창을 표시하지 않는다.
- 정상적으로 집중 시간이 끝난 경우에만 완료 여부를 묻는다.

## 6. 전체 완료 축하 이벤트

### 6.1 이벤트 정의

- 도메인 이벤트명: `TODO_ALL_COMPLETED`
- Tauri 프런트 이벤트명: `todo://all-completed`
- 이벤트 우선순위: 집중 경고, 발차기, 랜덤 대사와 일반 행동보다 높음
- 긴급 중지와 앱 종료보다 낮음

### 6.2 발동 조건

다음 조건을 모두 만족할 때 한 번 실행한다.

1. 판정 직전에 미완료 항목이 최소 한 개 있었다.
2. 사용자가 마지막 미완료 항목을 완료 처리했다.
3. 판정 직후 목록에 항목이 한 개 이상 존재한다.
4. 판정 직후 모든 항목이 완료 상태다.
5. 현재 전체 완료 상태에서 아직 축하 이벤트를 실행하지 않았다.

다음 경우에는 실행하지 않는다.

- 빈 목록
- 완료 항목만 있는 저장 데이터를 앱 시작 시 불러온 경우
- 마지막 미완료 항목을 삭제해서 전체 완료 상태가 된 경우
- 이미 전체 완료인 상태에서 완료 항목의 내용만 수정한 경우

### 6.3 재발동 규칙

- 새 미완료 항목을 추가하면 다시 발동 가능하다.
- 완료 항목 하나를 미완료로 바꾸면 다시 발동 가능하다.
- 이후 다시 모든 항목을 완료하면 새 축하 이벤트를 실행한다.
- 동일한 전체 완료 상태에서는 앱 재시작 후에도 중복 실행하지 않는다.

### 6.4 연출 순서

1. `0.0초`: 마지막 항목의 완료 표시를 먼저 반영한다.
2. `0.0~0.5초`: 이벤트를 예약하고 중복 트리거를 잠근다.
3. `0.5~1.2초`: 감자봇이 현재 행동을 중단하고 화면 중앙에 가까운 안전 위치로 이동한다.
4. `1.2~2.2초`: 점프 또는 만세 애니메이션을 실행한다.
5. `1.2~4.2초`: 폭죽과 색종이 효과를 최대 3초간 표시한다.
6. `1.4초`: 말풍선으로 축하 대사를 표시한다.
7. 설정이 켜져 있으면 축하 효과음을 한 번 재생한다.
8. 약 `4.5초`: 효과와 말풍선을 닫고 평상시 행동으로 복귀한다.

중앙 이동 시 작업표시줄과 모니터 경계를 침범하지 않는다. 다중 모니터에서는 펫이 현재 위치한 모니터의 작업 영역을 기준으로 한다.

### 6.5 축하 대사

기본 대사: `할렐루야! 다 끝났다!`

랜덤 후보:

- `이것이 바로 인간 승리다!`
- `오늘도 데프콘에 한 걸음 가까워졌다!`
- `설마 진짜 다 할 줄이야! 미안하다!`

사용자 지정 대사는 앞뒤 공백 제거 후 1~80자만 허용한다. 값이 비었거나 유효하지 않으면 기본 대사를 사용한다.

### 6.6 동시 이벤트와 예외 처리

- 축하 이벤트가 시작되면 발차기, 랜덤 대사, 춤과 커서 추적을 대기시킨다.
- 진행 중 새 할 일이 추가돼도 시작된 연출은 끝까지 실행한다. 종료 후 목록은 미완료 상태로 판정한다.
- 같은 사용자 동작에서 여러 항목이 완료돼도 이벤트 큐에는 한 번만 등록한다.
- 방해금지 모드에서도 시각 축하는 실행한다. 효과음은 사용자 설정을 따른다.
- `움직임 줄이기`가 켜져 있으면 중앙 이동과 반복 점프를 생략하고 말풍선과 간단한 색종이 효과만 사용한다.
- 긴급 중지가 실행되면 축하 연출을 즉시 취소하고 펫 창을 숨긴다.

## 7. 사용자 설정

축하 설정은 기존 설정 화면의 WinDbg 스타일을 유지하며 로컬 `settings.json`에 저장한다.

- `축하 효과음 사용`: 기본 켜짐. 꺼져 있어도 시각 축하는 실행한다.
- `움직임 줄이기`: 기본 꺼짐. 켜면 중앙 이동과 반복 점프를 생략한다.
- `다음 집중 자동 시작`: 기본 꺼짐. 꺼져 있으면 `다음 집중 시작` 선택 후 시작 준비 상태에 머문다.
- `사용자 지정 축하 대사`: 선택 입력, 앞뒤 공백 제거 후 1~80자. 빈 값은 기본·랜덤 대사를 사용한다.

## 8. 로컬 데이터 계약

투두 데이터는 앱 데이터 디렉터리의 `todo.json`에 원자적으로 저장한다. 손상 JSON은 기존 설정·GAMCHA 저장과 같은 방식으로 별도 보존하고 안전한 빈 목록을 연다.

```text
TodoItem
  id: string
  text: string
  createdAt: ISO-8601 string
  completedAt: ISO-8601 string | null

TodoState
  schemaVersion: number
  items: TodoItem[]
  selectedTodoId: string | null
  allCompletedCelebrated: boolean

FocusTodoLink (실행 중 메모리 상태)
  todoId: string | null
  titleAtStart: string | null
```

- 정렬의 기준은 `createdAt`이며 같은 값이면 저장 배열 순서를 유지한다.
- 세션 연결은 ID 기준이고 `titleAtStart`는 사용자에게 시작 당시 문맥을 보여주기 위한 snapshot이다.
- 앱 시작 시 완료 항목만 있어도 `allCompletedCelebrated`를 되돌리거나 축하 이벤트를 재생하지 않는다.

## 9. 접근성·안전 기준

- 입력창에서 `Enter`로 추가할 수 있고 모든 항목 동작은 `Tab`과 `Enter` 또는 `Space`로 실행할 수 있어야 한다.
- 완료 여부와 집중 선택은 색만으로 구분하지 않고 체크 상태·텍스트·접근성 이름을 함께 사용한다.
- 삭제 확인창은 기본 포커스를 취소에 둔다.
- 축하 연출은 다른 Windows 앱을 이동·최소화하거나 포커스를 빼앗지 않는다.
- 할 일 본문을 로그, 전경 감지 이벤트나 분석 데이터에 남기지 않는다.

## 10. 구현 순서

1. Rust `TodoItem`·`TodoState` 도메인 규칙과 전체 완료 판정 테스트
2. `todo.json` 저장·복구 서비스와 손상 파일 보존 테스트
3. CRUD·선택·조회 Tauri command와 `todo://changed` 이벤트
4. `PomodoroService`에 시작 시점 `FocusTodoLink`와 정상 완료 결과 연결
5. 독립 `todo` 창의 투두 UI, 500ms 지연 정렬과 키보드 조작
6. 정상 집중 종료의 완료·계속·다음 집중 선택 UI
7. `TODO_ALL_COMPLETED` 이벤트 잠금·재발동·긴급 취소
8. 펫 중앙 이동, 말풍선, 색종이와 움직임 줄이기 분기
9. 설정 저장, 전체 자동 테스트와 Windows 수동 검증

## 11. 완료 게이트

- 빈 값과 200자 초과를 거부하고 CRUD·선택이 재시작 후 복원된다.
- 미완료 우선·그룹 내 생성 순서와 완료 후 500ms 지연 이동이 동작한다.
- 집중 시작 시 선택 ID를 고정하고 실행 중 선택 변경이 현재 세션을 바꾸지 않는다.
- 정상 집중 완료에서만 완료 여부를 묻고 Skip·Stop은 항목을 변경하지 않는다.
- 삭제로 전체 완료가 된 경우와 앱 시작 시 완료 데이터에는 축하가 나오지 않는다.
- 마지막 미완료 항목의 사용자 완료에서만 축하가 한 번 발생하고 재발동 규칙과 재시작 중복 방지가 동작한다.
- 긴급 중지가 축하를 즉시 취소하며 움직임 줄이기 설정이 적용된다.
- 키보드만으로 추가·선택·완료·수정·삭제와 종료 선택이 가능하다.
- Rust·TypeScript 테스트, rustfmt, Clippy와 production build가 통과한다.
