# 01. 범위와 우선순위

## P0 — 반드시 완성

- Node.js, Rust, WebView2와 Windows C++ build tools 확인
- Tauri 2 + Vite + 순수 TypeScript 프로젝트 신규 생성
- Tauri 트레이와 투명 펫 창
- Idle, Walk, 방향 전환
- 단일/다중 모니터 작업 영역 경계
- 클릭, 드래그, 던지기와 3초 내 착지
- 뽀모도로 시작, 일시정지, 재개, 건너뛰기, 중지
- 프로세스명/창 제목 기반 방해 규칙
- 집중 중 감지 유예 시간과 쿨다운
- 경고 후 대상 재검증과 해당 창 최소화
- 기본 보호 목록과 실패 시 안전한 건너뛰기
- 긴급 중지와 트레이 재시작
- 로컬 설정 저장과 손상 파일 복구
- 핵심 단위·통합 테스트

## P1 — 핵심 경로 후 추가

- 대사와 말풍선
- 춤
- 클릭 반응과 10초 내 7회 이스터에그
- 집중 중 비활동 경고와 순수 발차기 연출
- Windows 알림

신규 개발에서는 P1을 기본 일정에 넣지 않는다. P0 release 빌드가 20시간 이전에 성공한 경우에만 최대 1개를 선택한다.

## P2 — 시간이 남을 때만

- WinDbg/Hyper-V 테마 카드
- 액세서리 선택 UI
- 자동 시작
- 알림음
- 픽셀 단위 투명 hit-test 고도화
- 고급 설정 화면 스타일링

## 이번 개발에서 제외

- macOS, Linux, Windows 10
- 계정, 동기화, 분석, 온라인 상점
- 브라우저 확장 또는 URL 감시
- 네트워크 차단과 앱 강제 종료
- 파일 생성·이동·삭제와 임의 프로그램 실행
- 자동 업데이트와 코드 서명 완성
- 사용자용 캐릭터 팩 편집기
- `네모` 캐릭터의 완성 연출

## 기능 절단 순서

일정이 부족하면 아래 순서대로 제거한다.

1. 카드
2. 액세서리 UI
3. 자동 시작과 알림음
4. 랜덤 대사 종류
5. 비활동 경고
6. 춤과 이스터에그

다음은 제거하지 않는다.

- 긴급 중지
- 대상 재검증
- 보호 창 판정
- 개입 기본 off
- 설정 저장
- 핵심 타이머 상태

## 시간별 중단선

| 시점 | 상태가 미달이면 |
|---:|---|
| 7시간 | 픽셀 hit-test를 포기하고 작은 사각 펫 창 사용 |
| 13시간 | 창 제목과 프로세스명 중 동작하는 규칙부터 완성 |
| 17시간 | 모든 P1/P2를 중단하고 핵심 개입 경로 수정 |
| 20시간 | 새 기능 추가 금지, 테스트와 릴리스만 수행 |

## 범위 변경 절차

새 기능 요청이 생기면 다음을 기록한다.

1. 어떤 사용자 문제를 해결하는가?
2. P0보다 중요한가?
3. 예상 작업 시간은 얼마인가?
4. 대신 제거할 기능은 무엇인가?
5. 안전 또는 개인정보 위험이 늘어나는가?

답이 불명확하면 현재 24시간 범위에 넣지 않는다.
